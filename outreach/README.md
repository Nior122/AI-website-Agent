# Outreach Preparation

Draft-only outreach uses the existing `TrackingStore` history and is eligible only after a qualified lead has a PASS validation, deployed preview URL, and approved human project review. Drafts are evidence-led, revision-preserving, and support EMAIL, WHATSAPP, INSTAGRAM, FACEBOOK, LINKEDIN, SMS, and OTHER formatting. `READY_TO_SEND` means approved for a future system only; this package has no sending capability.

Two things Phase 49 added belong to this package's contract even though the code that acts on them lives elsewhere. Every draft record now carries `content_fingerprint` and, once reviewed, `approved_content_fingerprint` - the SHA-256 of the recipient, subject, body, preview URL, channel, and personalization points - so an approval is bound to the exact content a human read, and an edit afterwards makes that approval visibly stale instead of silently reusable. Both digests are also written into the outreach review record beside the reviewer's attribution (`reviewed_by`, `identity_source`), which is what a later send reports as "who approved this text".

This package still has no sender. Sending is `orchestration/outbound.py`'s `ApprovedOutboundSender`, which re-reads the approval binding, the engagement ledger's eligibility guard, the opt-out blocks, the contact budget, and the automation hold at the moment of the send, marks the attempt durably, and performs at most one provider request. `READY_TO_SEND` therefore means "an operator may confirm one send of this content" - not "this will be sent", not "this was delivered", and never a queue a scheduler drains.
